# ADR-007: جلسات المبدع برموز مستقلة عن مستخدمي الإدارة

- الحالة: مقبول
- التاريخ: 2026-08-29
- المرحلة: 2

## السياق
المبدع ليس مستخدم Django ولا يملك كلمة مرور. هويته مثلثة: حساب TikTok
(`open_id`) + هاتف موثّق + بصمة جهاز. وثيقة المشروع تنص على JWT لخمس عشرة دقيقة
مع refresh مربوط بالجهاز، وعلى رفض مسارات الإدارة لأي رمز مبدع والعكس.

## القرار
1. تنفيذ رموز مستقل على PyJWT بدل ربطه بنموذج مستخدم Django.
2. ثلاثة أنواع: `preauth` عشر دقائق بعد ربط TikTok وقبل توثيق الهاتف ولا يفتح
   إلا مسار التحقق، `access` خمس عشرة دقيقة، `refresh` ثلاثون يومًا مربوط بجهاز.
3. رمز التجديد يُخزَّن مجزَّأً (SHA-256) لا نصًا، ويُدوَّر عند كل استعمال.
4. **كشف إعادة الاستعمال**: استعمال رمز مُبطَل يُبطل كل جلسات الجهاز فورًا.
5. `CreatorPrincipal` ليست مستخدم Django: `is_staff` و`is_superuser` تعيدان False
   دائمًا، فلا تفتح لها صلاحية إدارية بحال.
6. صلاحيتان متقابلتان: `IsCreator` ترفض جلسات الإدارة، و`IsAdminSession` ترفض
   رموز المبدعين.

## تفصيلة نفّذت بعد اكتشاف خلل
إبطال جلسات الجهاز عند كشف إعادة الاستعمال يجري في معاملة مستقلة، ثم يُرفع الخطأ
خارجها. لو رُفع داخل المعاملة لتراجع الإبطال مع التراجع وبقي الرمز المسروق صالحًا.
كشف ذلك اختبار `test_refresh_rotates_and_old_token_dies`.

## الأثر
لا يوجد مسار واحد يمنح مبدعًا صلاحية إدارية. مقابل ذلك، إدارة الرموز مسؤوليتنا
لا مسؤولية مكتبة جاهزة، ولذلك غُطّيت باختبارات صريحة.
