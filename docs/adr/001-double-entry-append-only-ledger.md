# ADR-001: دفتر مزدوج القيد بالإلحاق فقط، مع فحص توازن مؤجَّل

- الحالة: مقبول
- التاريخ: 2026-08-29
- المرحلة: 1

## السياق
تنص وثيقة المشروع على أن مجموع المدين يساوي مجموع الدائن لكل `txn_id`، وأن
`ledger_entries` و`audit_log` جدولا إلحاق فقط. قيد `CHECK` في PostgreSQL يعمل على
صف واحد ولا يرى بقية أسطر القيد، فلا يمكنه التعبير عن هذه القاعدة.

## القرار
1. فحص التوازن يُنفَّذ بـ `CONSTRAINT TRIGGER ... DEFERRABLE INITIALLY DEFERRED`
   يعمل عند إغلاق المعاملة، بعد إدراج كل الأسطر، ويقارن المجاميع لكل
   `(txn_id, currency)`.
2. منع التعديل والحذف بـ `BEFORE UPDATE/DELETE TRIGGER` يرفع استثناءً.
3. حارس ثانٍ على مستوى النموذج في بايثون لرسالة خطأ واضحة، لكن المرجع هو حارس
   قاعدة البيانات لا الكود.
4. سطر واحد إما مدين أو دائن، وليس كليهما ولا صفرًا — قيد `CHECK` عادي يكفي هنا.
5. الكتابة في الدفتر تمر حصريًا عبر `apps.ledger.services.post_transaction`.

## البدائل المرفوضة
- فحص التوازن في الكود فقط: أي مسار جديد أو أمر إداري قد يتجاوزه.
- `CHECK` على مستوى الصف: لا يستطيع رؤية مجموع القيد.

## الأثر
لا يمكن إنشاء قيد غير متوازن حتى بتجاوز الـ ORM. مقابل ذلك، اختبار التوازن
داخل معاملة اختبار يحتاج `SET CONSTRAINTS ALL IMMEDIATE` لإجبار الفحص.
