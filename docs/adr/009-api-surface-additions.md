# ADR-009: إضافتان على سطح الـ API مع تبريرهما

- الحالة: مقبول
- التاريخ: 2026-08-29
- المرحلة: 2

## السياق
قائمة المسارات في وثيقة المشروع لا تشمل مسارًا لتجديد الرموز، ولا مسارًا لإرسال
رمز OTP، مع أنها تنص على وجود refresh وعلى قراءة OTP آليًا.

## القرار
1. **إضافة `POST /api/v1/auth/refresh`**: بدونه يكون رمز التجديد المنصوص عليه بلا
   فائدة، ويضطر التطبيق إلى إعادة رحلة الربط كل ربع ساعة.
2. **عدم إضافة مسار لإرسال OTP**: `POST /auth/phone/verify` يرسل الرمز حين يصل
   بلا `code`، ويتحقق منه حين يصل معه. سطح الـ API يبقى كما في الوثيقة.

## الأثر
مسار واحد جديد فقط. أي إضافة أخرى تحتاج موافقة صريحة.
